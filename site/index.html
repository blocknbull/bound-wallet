A wallet for AI agents with limits the agent cannot change.

Bound is a NEAR smart contract that holds the funds. You set spending limits, who can be paid, and an amount above which the agent has to ask you. The agent gets a key that can only call one method on that contract. Every decision it makes is recorded on chain.

Why

A NEAR access key limits gas, not money.

The usual way to give an agent a wallet is a function-call key. Its allowance caps the gas the key can spend. It does not cap the value a call can move. A key scoped to a token's transfer method can send the entire balance in one call. Bound puts a contract between the key and the money.

01

The owner writes the policy.

Maximum per action and per rolling window, in NEAR or in dollars. A receiver allowlist, or approval for the first payment to anyone new. Which contracts and methods may be called. Active hours. A rate limit. An approval threshold.

02

The agent gets a key scoped to execute.

It is a normal NEAR function-call key, restricted to one contract and one method. The contract evaluates the policy before it moves anything. Owner methods check the caller's account and reject the agent.

03

Decisions are written on chain.

Executed, denied with the reason, queued for the owner, approved, rejected. The contract keeps its last 100 decisions and emits a NEP-297 event for each. A registry contract turns that history into a score per agent key.

Tripwire

Repeated denials suspend the agent.

A policy can set a number of denials and a window. When an agent hits that count, the contract marks it suspended and denies everything until the owner lifts it. This is the sequence recorded by guard.reins.testnet on 25 October with the tripwire set to 2 denials per hour.

For agents

One MCP server, four tools.

The config holds the agent's function-call key. If it leaks, the holder gets the same policy the agent had, nothing more. The owner can suspend or delete the key at any time.

bound_statusPolicy, remaining budget this window, counters, reputation if a registry is configured.
bound_checkEvaluates an action without executing it. Returns allowed, needs approval, or the denial reason.
bound_executeSubmits the action. Returns Executed, Denied with the reason, or Queued with an id.
bound_explain_denialTurns a denial reason into what the policy allows instead. Tells a suspended agent to stop retrying.

Comparison

A function-call key alone, and the same key behind Bound.

Function-call key on an accountFunction-call key on a Bound wallet
Value per callUnlimited. The allowance is a gas budget.Capped per action and per window, in NEAR or dollars.
ReceiversAny account the method accepts.Allowlist, or owner approval for new receivers.
Large actionsSent.Queued above a threshold until the owner approves.
Repeated denialsNot observed.Counted; the tripwire suspends the agent.
RecordTransaction logs, if indexed.Decision log in the contract, with reasons, plus events.
RevokingDelete the key.Delete the key, or suspend it and keep the history.
